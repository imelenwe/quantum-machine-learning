PEC, step by step

Probabilistic error cancellation, built up from one noisy qubit, with every number worked out by hand.

What PEC is trying to achieve

The goal: get the noise-free answer from a noisy quantum computer. Not a noise-free circuit (the circuits stay noisy), but the number you would have measured if there were no noise.

  • The problem. Noise pulls your measured answer away from the truth. You get 0.8 when the truth is 1.
  • What PEC can't do. It can't remove the noise from the chip, and it can't build a gate that undoes the noise. As we'll see, such a gate is impossible.
  • What PEC does instead. It runs a few slightly changed versions of your circuit. Each one is pulled away from the truth in a different, known way. Some results are added and some are subtracted, in just the right amounts, so the pulls cancel. What's left is the true answer.
  • The price. Subtracting makes the final number shakier, so you need many more shots. Every extra gate makes it shakier still, which is why PEC gets expensive for big circuits.

The process, start to finish

This is what happens when you switch PEC on (in the lab: resilience.pec_mitigation = True). IBM's software does all five steps automatically.

  1. Learn the noise. Before your circuit, run short test circuits to measure how noisy each gate is, for example "this gate flips the qubit 10% of the time."
  2. Work out the undo (on a normal computer). From that noise level, calculate a recipe: which versions of the circuit to run, how often, and which results get a minus sign.
  3. Build the versions. For each run, "roll a dice" for each gate: usually leave it alone, sometimes insert an extra gate (such as an X) right after it.
  4. Run them on the chip. Every version is an ordinary circuit. Nothing special happens on the hardware.
  5. Combine the results (on a normal computer). Flip the sign of the results marked "minus", average everything, and multiply by one number, called γ (gamma).

The rest of this page shows why that recipe gives the noise-free answer, and where the cost comes from.

The example we'll use, and why

  • One qubit, starting at |0⟩.
  • One gate that should do nothing. So the ideal answer is ⟨Z⟩ = 1: the qubit should still be measured as 0 every time.
  • The noise: 10% of the time, the gate accidentally flips the qubit (an X flip).

Why this example: it's the smallest case that still shows everything PEC does. There's only one kind of error, so every step can be done by hand with simple fractions, and we always know the right answer (1) to check against. Real hardware just has more gates and more kinds of flips. The steps stay the same.

Two symbols, used throughout: I means "do nothing" and X means "flip the qubit". One rule: flipping twice is the same as not flipping, so X then X = I.

The derivation

Step 1

Write the noise as a mix

"90% of the time do nothing, 10% of the time flip" is written as:

noise = 0.9·I + 0.1·X

Applying two of these one after the other works like multiplying brackets in algebra, because the chances multiply:

(0.9·I + 0.1·X) × (0.9·I + 0.1·X)
= 0.81·I + 0.09·X + 0.09·X + 0.01·(X then X)
= 0.82·I + 0.18·X

A real mix always adds up to 1 (0.82 + 0.18 = 1). Two noisy steps give 18% flips, not 20%, because the cases that flip twice end up back where they started.

The proper notation (what the shorthand stands for). A channel says what happens to the qubit's state ρ:

noise(ρ) = 0.9·ρ + 0.1·XρX

"0.9·I + 0.1·X" is just this with ρ left out. Multiplying out brackets is allowed because channels are linear in ρ. "X then X = I" holds because X·X = I, so X(XρX)X = ρ.

Step 2

Solve for the "undo", and find a negative number

2a. What we want. Our gate should do nothing, so the ideal gate is I. The hardware gives us the noisy gate instead. We want something that, applied after the noisy gate, gives back the ideal:

ideal = noisy, then undo

2b. Fill in what we know. Ideal = I. Noisy = 0.9·I + 0.1·X (from Step 1). The undo is unknown, but it can only be built from the same two pieces, "do nothing" and "flip", so guess it has the same shape with unknown weights a and b:

undo = a·I + b·X

Put all three into 2a:

I = (0.9·I + 0.1·X) then (a·I + b·X)

2c. Multiply out the brackets, exactly as in Step 1: every piece of the first bracket meets every piece of the second.

0.9·I then a·I = 0.9a·I
0.9·I then b·X = 0.9b·X
0.1·X then a·I = 0.1a·X
0.1·X then b·X = 0.1b·(X then X) = 0.1b·I   ← because X then X = I

Add the four pieces, putting the I's together and the X's together:

I = (0.9a + 0.1b)·I + (0.1a + 0.9b)·X

2d. Match both sides. The left side is 1·I + 0·X. For the two sides to be equal, the amount of I must match and the amount of X must match. That gives two equations:

I part: 0.9a + 0.1b = 1
X part: 0.1a + 0.9b = 0

2e. Solve. Start with the X part, because its right side is 0:

0.1a + 0.9b = 0
0.1a = −0.9b
a = −9b

Put a = −9b into the I part:

0.9·(−9b) + 0.1b = 1
−8.1b + 0.1b = 1
−8b = 1
b = −1/8

And back into a = −9b:

a = −9 × (−1/8) = 9/8

So:

undo = (9/8)·I − (1/8)·X    (a = 1.125, b = −0.125)

b is negative. A real recipe can't say "flip −12.5% of the time." So the undo cannot be built on any hardware. It exists only on paper.

The numbers still add to 1 (9/8 − 1/8 = 1), so it's a "sort-of probability", called a quasi-probability.

Step 3

Turn the undo into circuits we can run

Go back to 2a and put in the undo we just found:

ideal = noisy, then undo
= noisy, then ((9/8)·I − (1/8)·X)
= (9/8)·(noisy, then I) − (1/8)·(noisy, then X)
= (9/8)·(noisy) − (1/8)·(noisy, then an extra X)

The last line uses "noisy, then I" = "noisy", because I does nothing.

Both pieces are things the hardware can run:

  • Circuit 1: run the noisy gate normally.
  • Circuit 2: run the noisy gate, then add one extra X gate on purpose.

The impossible undo has been spread over two possible circuits. What's left is the job of combining them.

Step 4

Combine the measured answers, not the circuits

You can't "run a combination" of circuits. You can only run one circuit at a time and measure it. But the measured answers combine in the same way, because an expectation value is a trace, and the trace is linear:

⟨Z⟩ = Tr(Z·ρ)   and   Tr(Z·(a·ρ₁ + b·ρ₂)) = a·Tr(Z·ρ₁) + b·Tr(Z·ρ₂)

So the ideal answer follows the same recipe:

⟨Z⟩ ideal = (9/8)·⟨Z⟩ from circuit 1 − (1/8)·⟨Z⟩ from circuit 2

Circuit 1. The state after the noisy gate holds the chances: 90% still |0⟩, 10% flipped to |1⟩. Z gives +1 for |0⟩ and −1 for |1⟩.

ρ₁ = 0.9·|0⟩⟨0| + 0.1·|1⟩⟨1|
⟨Z⟩₁ = Tr(Z·ρ₁) = 0.9 − 0.1 = 0.8

Circuit 2. The extra X swaps |0⟩ and |1⟩. A gate acts on a state from both sides (X·ρ·X); a measurement goes inside the trace once (Tr(Z·ρ)).

ρ₂ = X·ρ₁·X = 0.9·|1⟩⟨1| + 0.1·|0⟩⟨0|
⟨Z⟩₂ = Tr(Z·ρ₂) = −0.9 + 0.1 = −0.8

Combine:

(9/8)·(0.8) − (1/8)·(−0.8) = 0.9 + 0.1 = 1  ✓ the noise-free answer

This is the heart of PEC: two noisy answers, combined with the right weights, give exactly the noise-free answer. The ideal state is never built; only its measured value is reconstructed.

Step 5

Make the negative weight runnable: γ appears

On hardware you choose how often to run each circuit, and "how often" can't be negative. So each weight is split into three parts:

weight = γ × chance × sign
Weight= γ× chance× sign
Circuit 19/810/80.9+1
Circuit 2−1/810/80.1−1
  • γ = the sizes of the weights added up (ignoring signs): 9/8 + 1/8 = 10/8 = 1.25.
  • Chance = each size divided by γ. The chances 0.9 and 0.1 are ordinary probabilities: positive, adding to 1. They decide which circuit to run.
  • Sign = where the minus went. It's no longer on "how often"; it's applied to the number you write down.

So the recipe the hardware actually follows is:

  1. 90% of the runs: run circuit 1 and write down its result as it is.
  2. 10% of the runs: run circuit 2 and write down its result with the sign flipped.
  3. Average everything written down, then multiply by γ.
average = 0.9 × (0.8) + 0.1 × (+0.8) = 0.8
× γ = 0.8 × 1.25 = 1  ✓

The average alone is still 0.8. Multiplying by γ is what lifts it back to the true answer.

Step 6

Two gates in a row: γ multiplies

Real circuits have many gates, and each noisy gate needs its own undo. Take two gates in a row, both with the same 10% flip, so each has the same recipe. For each gate there are two choices: plain (weight 9/8) or with an extra X after it (weight −1/8). Two gates × two choices = four circuits:

Gate 1Gate 2Weight
Circuit 1plainplain(9/8)·(9/8) = 81/64
Circuit 2plain+ extra X(9/8)·(−1/8) = −9/64
Circuit 3+ extra Xplain(−1/8)·(9/8) = −9/64
Circuit 4+ extra X+ extra X(−1/8)·(−1/8) = +1/64

These are the four terms you get by multiplying out the two brackets. Here "multiply" means "do one channel, then the other", since we're combining channels, not gate matrices. Each weight is the two gates' weights multiplied, so the signs multiply too.

γ for the circuit = 81/64 + 9/64 + 9/64 + 1/64 = 100/64 = (10/8) × (10/8)

The γ's multiply. 2 gates give γ², 10 gates give γ¹⁰, and t gates give γt.

Step 7

Why a big γ is costly: shots

A shot is one run of the circuit plus one measurement. A single shot gives only +1 or −1. ⟨Z⟩ is the average over many shots, so with a limited number of shots the average wobbles a little around the truth.

Why the wobble shrinks slowly. Think of a fair coin: heads = +1, tails = −1, true average 0.

  • Toss it 100 times. Ideally 50 heads and 50 tails, so the total is 0. In real life you might get 55 heads, so the total is +10. That +10 is how far the total landed from where it should be.
  • This is a random walk: each toss is a step forward or back. Over many runs, the squared distance averages exactly the number of steps. For 3 steps: (9 + 1 + 1 + 1 + 1 + 1 + 1 + 9) / 8 = 3. So the total typically ends about √N away (√100 = 10).
  • The average divides the total by N, so it's off by about √N ÷ N:
ShotsTotal typically off byAverage off by
100√100 = 1010 ÷ 100 = 0.10
10,000√10,000 = 100100 ÷ 10,000 = 0.01

100× more shots only makes the answer 10× more accurate. To make the wobble k times smaller, you need k² times more shots.

Where γ comes in. PEC's last step multiplies the average by γ, and that multiplies the wobble by γ too. To shrink it back down you need γ² times more shots.

10 gates at 10% noise:  γ = 1.25¹⁰ ≈ 9.3  →  shots needed ≈ 9.3² ≈ 87× more

Real hardware has much less noise per gate, but real circuits have hundreds of gates, so the cost still grows very fast. That's why the lab estimates about 4.5 minutes of QPU time for PEC, against 16 seconds for ZNE.

Any noise level

The same recipe for any flip chance p

Repeat Step 2 with flip chance p instead of 0.1. The noisy gate is (1 − p)·I + p·X. Multiplying out and matching, exactly as in 2c and 2d, gives:

I part: (1 − p)·a + p·b = 1
X part: p·a + (1 − p)·b = 0

From the X part:

a = −(1 − p)·b / p

Put that into the I part:

−(1 − p)²·b / p + p·b = 1
b·(p² − (1 − p)²) / p = 1
b·(2p − 1) / p = 1   ← because p² − (1 − p)² = p² − 1 + 2p − p² = 2p − 1
b = p / (2p − 1) = −p / (1 − 2p)

Back into a, then add the sizes to get γ:

a = (1 − p) / (1 − 2p)
γ = |a| + |b| = (1 − p + p) / (1 − 2p) = 1 / (1 − 2p)

With p = 0.1 this gives back 9/8, −1/8 and 10/8. The weights come straight from how noisy the gate is: a noisier gate gives bigger weights, a bigger γ, and more shots.

Summary

PEC doesn't fix the noisy circuit. It runs several noisy versions and combines their results with pluses and minuses, so the noise cancels out in the final answer.

  • The perfect "undo" needs a negative amount, so it can't be built. It's used only on paper.
  • On paper, the ideal gate becomes a combination of circuits the hardware can run.
  • The measured answers combine the same way (the trace is linear), so the noise-free answer can be computed from noisy runs.
  • Negative weights become chance × sign × γ: run versions by chance, flip some results, average, and multiply by γ.
  • γ multiplies gate by gate, and the cost is γ² times more shots.
