PEC, step by step

Probabilistic error cancellation, built up from one noisy qubit, with every number worked out by hand. Each step starts with a short "where we are" box, so you always know what the previous step gave us.

What PEC is trying to achieve

The goal: get the noise-free answer from a noisy quantum computer. Not a noise-free circuit (the circuits stay noisy), but the number you would have measured if there were no noise.

  • The problem. Noise pulls your measured answer away from the truth. You get 0.8 when the truth is 1.
  • What PEC can't do. It can't remove the noise from the chip, and it can't build a gate that undoes the noise. As we'll see in Step 2, such a gate is impossible.
  • What PEC does instead. On paper, it writes each ideal gate as a weighted mix of parts the hardware can run (for example, "the noisy gate" and "the noisy gate followed by an extra X"). Some weights are positive and some are negative. On each run, it picks one part of each gate, with a probability that matches its weight, runs that circuit, and keeps track of the sign. Averaged over many runs, the parts add up to the ideal gate, so the average gives the noise-free answer.
  • The price. Because some parts carry a minus sign, the results partly cancel each other, and the final average has to be scaled up by a number called γ. That makes it shakier, so you need many more shots. Every gate in the circuit multiplies γ again, which is why PEC gets expensive for big circuits.

The process, start to finish

This is what happens when you switch PEC on (in the lab: resilience.pec_mitigation = True). IBM's software does all five steps automatically.

  1. Learn the noise. Before your circuit, run short test circuits to measure how noisy each gate is, for example "this gate flips the qubit 10% of the time."
  2. Work out the undo (on a normal computer). From that noise level, calculate a recipe: what the parts of each ideal gate are, how often to pick each part, and which results get a minus sign.
  3. Pick the parts. For each run, pick one part of each gate, using that part's probability: usually the gate alone, sometimes the gate with an extra gate (such as an X) right after it.
  4. Run them on the chip. Every circuit built this way is an ordinary circuit. Nothing special happens on the hardware.
  5. Combine the results (on a normal computer). Flip the sign of the results marked "minus", average everything, and multiply by one number, called γ (gamma).

The derivation below shows why that recipe gives the noise-free answer, and where the cost comes from. Steps 1–4 explain "work out the undo" and "combine". Steps 5–7 explain picking the parts and γ. Step 8 explains the cost.

The example we'll use, and why

  • One qubit, starting at |0⟩.
  • One gate that should do nothing. So the ideal answer is ⟨Z⟩ = 1: the qubit should still be measured as 0 every time.
  • The noise: 10% of the time, the gate accidentally flips the qubit (an X flip).

Why this example: it's the smallest case that still shows everything PEC does. There's only one kind of error, so every step can be done by hand with simple fractions, and we always know the right answer (1) to check against. Real hardware just has more gates and more kinds of flips. The steps stay the same.

Two symbols, used throughout: I means "do nothing" and X means "flip the qubit". One rule: flipping twice is the same as not flipping, so X then X = I.

Step 1

Write the noise as a mix

Where we are: we have a gate that should do nothing, but flips the qubit 10% of the time. Before we can undo that, we need a way to write it down and a way to calculate with it.

1aWrite it down

"90% of the time do nothing, 10% of the time flip" is written as:

noise = 0.9·I + 0.1·X

Read "0.9·I" as "with weight 0.9, do I". The weights are the probabilities, so they add up to 1.

1bCalculate with it: two noisy steps in a row

Why we do this: Step 2 will need to put "one thing, then another" together. The simplest place to learn how is two noisy steps in a row.

Each step either flips or doesn't, so there are four paths. On each path, the probabilities multiply:

First stepSecond stepProbabilityOverall
no flip (I)no flip (I)0.9 × 0.9 = 0.81I
no flip (I)flip (X)0.9 × 0.1 = 0.09X
flip (X)no flip (I)0.1 × 0.9 = 0.09X
flip (X)flip (X)0.1 × 0.1 = 0.01X then X = I

Those four rows are exactly what you get by multiplying out the brackets, as in school algebra: every piece of the first bracket meets every piece of the second.

(0.9·I + 0.1·X) then (0.9·I + 0.1·X)
= 0.81·I + 0.09·X + 0.09·X + 0.01·(X then X)
= 0.81·I + 0.09·X + 0.09·X + 0.01·I   ← X then X = I
= 0.82·I + 0.18·X   ← collect the I's and the X's

Two noisy steps give 18% flips, not 20%, because the path that flips twice ends up back where it started.

The rule we take forward: to put "one mix, then another" together, multiply out the brackets and use X then X = I.

The proper notation (what the shorthand stands for). A channel says what happens to the qubit's state ρ (its density matrix; Step 4 works with it in detail):

noise(ρ) = 0.9·ρ + 0.1·XρX

"0.9·I + 0.1·X" is just this with ρ left out. Multiplying out brackets is allowed because channels are linear in ρ. "X then X = I" holds because X·X = I, so X(XρX)X = ρ.

Step 2

Solve for the "undo", and find a negative number

From Step 1: noisy = 0.9·I + 0.1·X, and "one thing, then another" is worked out by multiplying out the brackets. Now we use that to find what would cancel the noise.

2aWhat we want

Our gate should do nothing, so the ideal gate is I. The hardware gives us the noisy gate instead. We want something that, applied after the noisy gate, gives back the ideal:

ideal = noisy, then undo

2bFill in what we know

Ideal = I. Noisy = 0.9·I + 0.1·X (from Step 1). The undo is unknown, but it can only be built from the same two pieces, "do nothing" and "flip", so guess it has the same shape with unknown weights a and b:

undo = a·I + b·X

Put all three into 2a:

I = (0.9·I + 0.1·X) then (a·I + b·X)

2cMultiply out the brackets

Exactly as in Step 1: every piece of the first bracket meets every piece of the second.

0.9·I then a·I = 0.9a·I
0.9·I then b·X = 0.9b·X
0.1·X then a·I = 0.1a·X
0.1·X then b·X = 0.1b·(X then X) = 0.1b·I   ← because X then X = I

Add the four pieces, putting the I's together and the X's together:

I = (0.9a + 0.1b)·I + (0.1a + 0.9b)·X

2dMatch both sides

The left side is 1·I + 0·X. For the two sides to be equal, the amount of I must match and the amount of X must match. That gives two equations:

I part: 0.9a + 0.1b = 1
X part: 0.1a + 0.9b = 0

2eSolve

Start with the X part, because its right side is 0:

0.1a + 0.9b = 0
0.1a = −0.9b
a = −9b

Put a = −9b into the I part:

0.9·(−9b) + 0.1b = 1
−8.1b + 0.1b = 1
−8b = 1
b = −1/8

And back into a = −9b:

a = −9 × (−1/8) = 9/8

So:

undo = (9/8)·I − (1/8)·X    (a = 1.125, b = −0.125)

b is negative. The undo would have to say "flip −12.5% of the time". A probability can't be negative, so the undo cannot be built on any hardware. It exists only on paper.

The numbers still add to 1 (9/8 − 1/8 = 1), so it's a "sort-of probability", called a quasi-probability.

Step 3

Turn the undo into circuits we can run

From Step 2: undo = (9/8)·I − (1/8)·X, and it can't be built. But its two pieces, I and X, are ordinary gates. So we split the undo into its pieces.

3aPut the undo into 2a

ideal = noisy, then undo
= noisy, then ((9/8)·I − (1/8)·X)

3bSplit it

"Noisy, then (a bracket)" is multiplied out just like in Step 1: the noisy gate meets each piece of the bracket in turn, and each piece keeps its weight:

= (9/8)·(noisy, then I) − (1/8)·(noisy, then X)
= (9/8)·(noisy) − (1/8)·(noisy, then an extra X)   ← "then I" does nothing

3cRead off the circuits

Both pieces are things the hardware can run:

  • Circuit 1: run the noisy gate normally. Weight +9/8.
  • Circuit 2: run the noisy gate, then add one extra X gate on purpose. Weight −1/8. The extra X is the X piece of the undo, now run as a real gate.

The impossible undo has been spread over two possible circuits. The minus sign is now on a weight, not on a gate.

Where did the noise go? Nowhere. Both circuits start with the same real noisy gate; the noise is never removed. What got split in two is the undo: its I piece became "nothing extra" and its X piece became "an extra X".

So the ideal gate is made of two parts, each with a weight:

ideal gate = (9/8)·(part 1) − (1/8)·(part 2)
part 1 = the noisy gate, nothing after it
part 2 = the noisy gate, then an extra X

Neither part is the ideal gate on its own. Only the weighted combination is.

Note: this example has two parts because its noise has only one kind of error (the X flip). Real noise can have more kinds of error (X, Y and Z flips, or flips on two qubits at once), and each kind adds one more part, so a gate can have 4, 16 or more parts. Step 7c shows how many.

Next: we can't run "9/8 of a circuit minus 1/8 of another", so Step 4 works out how to use the weights.

Step 4

Combine the measured answers, not the circuits

From Step 3: ideal = (9/8)·(circuit 1) − (1/8)·(circuit 2). We can run each circuit, but only one at a time. This step shows the weights can be applied to the measured numbers instead.

4aName things

Call the state at the end of each circuit, and the number we measure from it:

circuit 1 (noisy gate)   → end state ρ₁  → measured answer ⟨Z⟩₁
circuit 2 (noisy gate, then extra X)   → end state ρ₂  → measured answer ⟨Z⟩₂

Step 3 says the ideal state is the same mix of the two end states:

ρ ideal = (9/8)·ρ₁ − (1/8)·ρ₂

4bWhy the answers combine the same way

A measured answer is a trace: ⟨Z⟩ = Tr(Z·ρ). The trace is linear, which means weights can be pulled out of it: Tr(c·A + d·B) = c·Tr(A) + d·Tr(B). So:

⟨Z⟩ ideal = Tr(Z·ρ ideal)
    = Tr(Z·((9/8)·ρ₁ − (1/8)·ρ₂))
    = (9/8)·Tr(Z·ρ₁) − (1/8)·Tr(Z·ρ₂)   ← pull the weights out
    = (9/8)·⟨Z⟩₁ − (1/8)·⟨Z⟩₂

So we need two numbers, ⟨Z⟩₁ and ⟨Z⟩₂. Each is found the same way: start from the input state, push it through the circuit to get the end state (ρ₁ or ρ₂), then measure Z with Tr(Z·end state). The next three parts do exactly that.

4cThe input, and the facts we'll use

The qubit starts in |0⟩ (ket zero). As a density matrix, a state |ψ⟩ is written |ψ⟩⟨ψ| (ket times bra), so the input is:

ρ = |0⟩⟨0|
X|0⟩ = |1⟩  and  X|1⟩ = |0⟩   ← X flips
⟨0|X = ⟨1|  and  ⟨1|X = ⟨0|   ← the same flip, on the bra side
Z|0⟩ = +|0⟩  and  Z|1⟩ = −|1⟩   ← Z reads 0 as +1 and 1 as −1
Tr(Z·|ψ⟩⟨ψ|) = ⟨ψ|Z|ψ⟩   ← so Tr(Z·|0⟩⟨0|) = +1 and Tr(Z·|1⟩⟨1|) = −1

4dCalculating ⟨Z⟩₁, from circuit 1 (just the noisy gate)

First the end state ρ₁. Circuit 1 is only the noisy gate, so apply the channel from Step 1, noise(ρ) = 0.9·ρ + 0.1·XρX, to the input ρ = |0⟩⟨0|:

ρ₁ = 0.9·|0⟩⟨0| + 0.1·X|0⟩⟨0|X
    = 0.9·|0⟩⟨0| + 0.1·|1⟩⟨1|   ← X|0⟩ = |1⟩ and ⟨0|X = ⟨1|

In words: 90% still |0⟩, 10% flipped to |1⟩.

Then measure Z on ρ₁. The trace is linear, so it goes through each piece:

⟨Z⟩₁ = Tr(Z·ρ₁)
    = 0.9·Tr(Z·|0⟩⟨0|) + 0.1·Tr(Z·|1⟩⟨1|)
    = 0.9·(+1) + 0.1·(−1)
    = 0.8

4eCalculating ⟨Z⟩₂, from circuit 2 (noisy gate, then an extra X)

First the end state ρ₂. Circuit 2 is circuit 1 with one more gate, X, at the end. So we don't start over: take ρ₁ (what comes out of the noisy gate) and apply X to it. A gate acts on a density matrix from both sides, X·ρ·X:

ρ₂ = X·ρ₁·X
    = 0.9·X|0⟩⟨0|X + 0.1·X|1⟩⟨1|X
    = 0.9·|1⟩⟨1| + 0.1·|0⟩⟨0|   ← X swaps 0 and 1 on both sides

In words: the extra X swapped the probabilities, so now 90% is |1⟩ and 10% is |0⟩.

Then measure Z on ρ₂:

⟨Z⟩₂ = Tr(Z·ρ₂)
    = 0.9·Tr(Z·|1⟩⟨1|) + 0.1·Tr(Z·|0⟩⟨0|)
    = 0.9·(−1) + 0.1·(+1)
    = −0.8

4fCombine

Put ⟨Z⟩₁ = 0.8 and ⟨Z⟩₂ = −0.8 into the recipe from 4b:

⟨Z⟩ ideal = (9/8)·⟨Z⟩₁ − (1/8)·⟨Z⟩₂
    = (9/8)·(0.8) − (1/8)·(−0.8)
    = 0.9 + 0.1 = 1  ✓ the noise-free answer

This is the heart of PEC: two noisy answers, combined with the right weights, give exactly the noise-free answer. The ideal state is never built; only its measured value is reconstructed.

Step 5

Two gates in a row: the circuits multiply

From Steps 1–4: one noisy gate needs 2 circuits, with weights +9/8 and −1/8. But real circuits have many gates, each with its own noise. What happens with two?

Three words, used from here on:

  • Gate: one gate in your circuit, e.g. our do-nothing gate. The hardware always runs it noisy.
  • Part: from Step 3, each ideal gate is made of 2 weighted parts: part 1 (the noisy gate alone, weight +9/8) and part 2 (the noisy gate then an extra X, weight −1/8).
  • Circuit: one complete run, with one part chosen for every gate.

5aThe setup

Two gates in a row, both should do nothing, both flip 10% of the time. Each noisy gate gets its own undo, right after it:

ideal = (noisy₁, then undo) then (noisy₂, then undo)

Each bracket is exactly the one-gate case, so Step 3 already split it:

noisy, then undo = (9/8)·(noisy) − (1/8)·(noisy, then X)

So:

ideal = [(9/8)·noisy₁ − (1/8)·(noisy₁, X)] then [(9/8)·noisy₂ − (1/8)·(noisy₂, X)]

5bMultiply out the brackets

Same rule as Steps 1 and 2: every piece of the first bracket meets every piece of the second, and the weights multiply:

(9/8)·(9/8)   = 81/64  : noisy₁, noisy₂
(9/8)·(−1/8)  = −9/64  : noisy₁, noisy₂, X
(−1/8)·(9/8)  = −9/64  : noisy₁, X, noisy₂
(−1/8)·(−1/8) = +1/64  : noisy₁, X, noisy₂, X

As a table, where "+ X" means an extra X right after that gate:

After gate 1After gate 2Weight
Circuit 1nothingnothing+81/64
Circuit 2nothing+ X−9/64
Circuit 3+ Xnothing−9/64
Circuit 4+ X+ X+1/64

Two things to notice. The signs multiply: a circuit gets a minus when it has an odd number of extra X's. And by Step 4, the ideal answer is these four measured answers combined with these four weights.

5cThe problem this shows

Each gate has 2 parts, so each gate doubles the number of circuits: 1 gate → 2, 2 gates → 4, 3 gates → 8, t gates → 2t.

100 gates → 2¹⁰⁰ ≈ 10³⁰ circuits

Nobody can run 10³⁰ circuits. So PEC can't run every circuit and combine them as in Step 4.

Next: Step 6 shows how to get the same answer by picking one part of each gate at random, instead of running every circuit.

Step 6

For each gate, pick one of its parts at random, by weight

From Step 5: every ideal gate is made of 2 parts (part 1: the noisy gate alone, part 2: the noisy gate then an extra X), and a circuit with many gates has far too many combinations to run them all. The way out: on each run, for each gate, pick one of its parts at random, and run the circuit those picks make. Over many runs, the picked parts add up, with the right weights, to the ideal gate. We work it out for one gate first (2 parts, weights +9/8 and −1/8). Step 7 does two gates.

What is picked at random, and what isn't. The random pick is which part of the gate to run. γ (gamma) is not random: it is one fixed number, worked out once from the weights, that every result is multiplied by at the end.

6aWhy the weights can't be used as probabilities directly

To pick at random, we need probabilities: numbers that are positive and add up to 1. Our weights fail the first test, because −1/8 is negative.

6bSplit each weight into size and sign

Write each weight as its size (ignoring the sign) times its sign:

+9/8 = (9/8) × (+1)
−1/8 = (1/8) × (−1)

The sizes are positive, but they add to 9/8 + 1/8 = 10/8, not 1. Call that total γ. Its job is to normalise the weights: dividing by γ turns the sizes into probabilities.

γ = 9/8 + 1/8 = 10/8 = 1.25

Divide each size by γ (normalise). Now they add to 1, so they are real probabilities:

probability of part 1 (noisy gate alone)     = (9/8) ÷ (10/8) = 9/10 = 0.9
probability of part 2 (noisy gate, extra X) = (1/8) ÷ (10/8) = 1/10 = 0.1

Putting it back together, every weight is γ × probability × sign:

Weight= γ× probability× sign
Part 1 (noisy gate alone)+9/810/80.9+1
Part 2 (noisy gate, extra X)−1/810/80.1−1

6cThe recipe

Each part of the weight now has one job:

  1. Probability decides which part to run. Before each run, pick part 1 with probability 0.9 or part 2 with probability 0.1. With only one gate, the part you pick is the whole circuit: part 1 = circuit 1, part 2 = circuit 2 (from Step 4).
  2. Sign is applied to the result you write down: a part-1 result as it is, a part-2 result with its sign flipped.
  3. γ is applied once at the end: average everything written down, then multiply by γ = 1.25.

6dWhy it isn't really "random"

The word "random" can sound like guessing. It isn't, for two reasons:

  • The pick is weighted, on purpose. It isn't a fair 50/50 pick. The probabilities 0.9 and 0.1 come straight from the weights, so part 1 (the bigger weight) is picked 9 times as often as part 2. Each part gets exactly its share.
  • The final answer isn't random. Any single run is a gamble, but over many runs the shares settle down: about 90% of the runs use part 1 and 10% use part 2. 6e shows that this average, times γ, is exactly the Step 4 answer. Randomness only decides the order of the runs; the long-run mix is fixed.

So "pick at random" really means: use each part in proportion to its weight, so that over many runs the parts add up to the ideal gate, without having to list every circuit. That last part matters in Step 7.

Note: our example has two parts, so there are only two probabilities. With more kinds of error there are more parts (see 7c); γ is still the sum of all the sizes, and each part's probability is its size ÷ γ. The recipe stays the same.

6eWhy the recipe gives the Step 4 answer

Over many runs, the circuit-1 runs average to ⟨Z⟩₁ and the circuit-2 runs average to ⟨Z⟩₂. With the probabilities and signs, the overall average is:

average = 0.9·(+1)·⟨Z⟩₁ + 0.1·(−1)·⟨Z⟩₂ = 0.9·⟨Z⟩₁ − 0.1·⟨Z⟩₂

Multiply by γ:

γ × average = 1.25·(0.9·⟨Z⟩₁ − 0.1·⟨Z⟩₂)
    = 1.125·⟨Z⟩₁ − 0.125·⟨Z⟩₂
    = (9/8)·⟨Z⟩₁ − (1/8)·⟨Z⟩₂   ← exactly the formula from 4b

6fWith our numbers

⟨Z⟩₁ = 0.8 and ⟨Z⟩₂ = −0.8 (from 4d and 4e):

average = 0.9·(+1)·(0.8) + 0.1·(−1)·(−0.8)
    = 0.72 + 0.08 = 0.8
γ × average = 1.25 × 0.8 = 1  ✓

The average alone is still 0.8. Multiplying by γ is what lifts it back to the true answer.

With only one gate, you could of course just run both circuits and use Step 4 directly. The random pick pays off when there are many gates, which is next.

Step 7

Many gates: pick a part for each gate, and γ multiplies

From Steps 5 and 6: two gates give four circuits with weights +81/64, −9/64, −9/64, +1/64. For one gate, we split weights into γ × probability × sign. Now do the same split for two gates.

7aγ for two gates

As in 6b, γ is the sizes of the weights added up:

γ = 81/64 + 9/64 + 9/64 + 1/64 = 100/64

And 100/64 = (10/8) × (10/8). That's no coincidence: the four sizes are exactly what you get by multiplying out (9/8 + 1/8) × (9/8 + 1/8), the one-gate sizes. So:

γ for two gates = (γ for one gate)² = 1.25² ≈ 1.56

The γ's multiply. t gates give γt.

7bThe probabilities: pick a part for each gate separately

As in 6b, each probability is size ÷ γ:

SizeProbability = size ÷ (100/64)= gate 1 × gate 2Sign
Circuit 1 (nothing, nothing)81/6481/1000.9 × 0.9+
Circuit 2 (nothing, + X)9/649/1000.9 × 0.1−
Circuit 3 (+ X, nothing)9/649/1000.1 × 0.9−
Circuit 4 (+ X, + X)1/641/1000.1 × 0.1+

Each circuit's probability is just the one-gate probabilities multiplied. That means we never need the full list of circuits. Instead, for each gate separately, pick a part with the same probabilities as in 6c: part 1 (nothing after it) with probability 0.9, part 2 (an extra X after it) with probability 0.1. The picks together build one circuit, and each circuit comes up with exactly the right probability. This is the "pick the parts" step of the process.

The sign is + or − depending on whether the number of extra X's is even or odd. Then, as in 6c: flip the sign of the minus results, average, multiply by γ = 100/64.

This works for any number of gates: one pick per gate, and one γt at the end. For 100 gates that's 100 picks per run, instead of a list of 2¹⁰⁰ circuits.

7cIs it always two parts per gate?

No. We got two because our noise had only one kind of error (the X flip), so the undo had two pieces, I and X. In general, an ideal gate has one part for "nothing extra", plus one part per kind of error:

Noise on the gateKinds of errorParts per gate
Our example: X flip onlyX2: nothing, X
One qubit, all flip typesX, Y, Z4: nothing, X, Y, Z
Two-qubit gate (e.g. CNOT)up to 15 (XI, IX, XX, …)up to 16

The steps don't change: solve for the undo (more unknowns, more equations), split each weight into γ × probability × sign, and pick one of more parts for each gate.

Step 8

Why a big γ is costly: shots

From Steps 6 and 7: the recipe ends by multiplying the average by γ, and γ grows as γt with the number of gates. This step shows why that makes PEC expensive.

8aShots, and why averages wobble

A shot is one run of the circuit plus one measurement. A single shot gives only +1 or −1. ⟨Z⟩ is the average over many shots, so with a limited number of shots the average wobbles a little around the truth.

8bHow big the wobble is: a coin

Think of a fair coin: heads = +1, tails = −1, true average 0. Toss it 3 times and add up. All 8 possible outcomes, equally likely:

TossesTotalTotal²
H H H+39
H H T+11
H T H+11
H T T−11
T H H+11
T H T−11
T T H−11
T T T−39

The totals average to 0, as they should. But the squared totals average to (9 + 1 + 1 + 1 + 1 + 1 + 1 + 9) / 8 = 24 / 8 = 3, the number of tosses. This holds for any number of tosses N: the squared total averages N. So the total typically lands about √N away from 0.

The average is the total divided by N, so it's off by about √N ÷ N:

Shots NTotal typically off by √NAverage off by √N ÷ N
1001010 ÷ 100 = 0.10
10,000100100 ÷ 10,000 = 0.01

100× more shots only makes the answer 10× more accurate. To make the wobble k times smaller, you need k² times more shots.

8cWhere γ comes in

PEC's last step multiplies the average by γ, and that multiplies the wobble by γ too. For example, with one gate, suppose the average comes out with a wobble of 0.10:

average ≈ 0.8 ± 0.10
× γ = 1.25  →  answer ≈ 1 ± 0.125

To shrink the wobble back down by a factor γ, 8b says you need γ² times more shots.

10 gates at 10% noise:  γ = 1.25¹⁰ ≈ 9.3  →  shots needed ≈ 9.3² ≈ 87× more

Real hardware has much less noise per gate, but real circuits have hundreds of gates, so the cost still grows very fast. That's why the lab estimates about 4.5 minutes of QPU time for PEC, against 16 seconds for ZNE.

Extra

The same recipe for any flip probability p

So far every number came from a 10% flip probability. Here is Step 2 again with a general flip probability p, to see how the weights and γ depend on the noise.

+aThe equations

The noisy gate is (1 − p)·I + p·X. Multiplying out and matching, exactly as in 2c and 2d, gives:

I part: (1 − p)·a + p·b = 1
X part: p·a + (1 − p)·b = 0

+bSolve

From the X part:

a = −(1 − p)·b / p

Put that into the I part:

−(1 − p)²·b / p + p·b = 1
b·(p² − (1 − p)²) / p = 1
b·(2p − 1) / p = 1   ← because p² − (1 − p)² = p² − 1 + 2p − p² = 2p − 1
b = p / (2p − 1) = −p / (1 − 2p)

Back into a, then add the sizes to get γ (a is positive and b is negative, so the sizes are a and −b):

a = (1 − p) / (1 − 2p)
γ = a − b = (1 − p + p) / (1 − 2p) = 1 / (1 − 2p)

The weights come straight from how noisy the gate is: a noisier gate gives bigger weights, a bigger γ, and more shots.

Summary

PEC doesn't fix the noisy circuit. For each gate it picks one of its parts, with probabilities set by the weights, runs the circuit those picks make, and combines their results with pluses and minuses, so the noise cancels out in the final answer.

  • Steps 1–2. The perfect "undo" needs a negative amount, so it can't be built. It's used only on paper.
  • Step 3. On paper, the ideal gate becomes a weighted combination of circuits the hardware can run.
  • Step 4. The measured answers combine the same way (the trace is linear), so the noise-free answer can be computed from noisy runs.
  • Step 5. Every gate doubles the number of circuits, so they can't all be run.
  • Steps 6–7. Weight = γ × probability × sign: γ normalises the weights into probabilities; pick one part per gate with those probabilities, flip the sign of some results, average, and multiply by γ. γ multiplies gate by gate.
  • Step 8. Multiplying by γ also multiplies the wobble, so PEC costs γ² times more shots.
