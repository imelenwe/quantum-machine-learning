Why Pauli twirling can make ZNE more effective

A walk-through using one qubit, one 12° gate error, and a bit of Bloch-sphere geometry.

The idea in one paragraph

ZNE (zero-noise extrapolation) deliberately runs a circuit at several amplified noise levels, for example by repeating gates in a way that should cancel out. It measures the answer at each level, then extends the trend backward to guess the answer at zero noise.

ZNE works best when the answer changes in a smooth, predictable way as the noise is turned up. Some kinds of error make that change jumpy and hard to predict. Pauli twirling reshapes those errors so the change becomes much more regular. Twirling isn't required for ZNE, but it often makes ZNE far more reliable.

Two kinds of gate error

  • Coherent error: a fixed, repeatable twist. For example, the gate always over-rotates by the same small angle. The Bloch arrow stays full length but points to the wrong place.
  • Incoherent (stochastic) error: random kicks. On average, the Bloch arrow gets shorter. ("Stochastic" just means random: each time, one of several possible errors happens, with set probabilities.)

Setup

  • The qubit starts at |0⟩, so the Bloch arrow points straight up.
  • We apply a gate that should do nothing overall, and repeat it k times.
  • The hardware has a coherent error: each time the gate fires, it over-rotates the arrow by an extra 12° around the X axis.
  • We measure ⟨Z⟩, the Z expectation value: how far "up" the arrow points. 1 = perfect, 0 = sideways, −1 = upside down. In measurement terms, ⟨Z⟩ = (chance of measuring 0) − (chance of measuring 1).

Without twirling: marching in a straight line

Every gate tilts the arrow 12° further in the same direction. The angles add up:

  • 1 gate → 12°
  • 3 gates → 36°
  • 5 gates → 60°
  • 15 gates → 180°, fully upside down
  • 30 gates → 360°, all the way round and back to perfect

The ⟨Z⟩ expectation value is cos(k × 12°). Plotted against k, this is a cosine wave: the arrow keeps its full length and keeps turning, so the measured value swings down and back up.

With Pauli twirling: a classical random walk

Twirling puts random Pauli gates (I, X, Y or Z) around each gate, and flips the result back afterwards so the ideal computation is unchanged. For this error, the effect is that each gate's extra 12° goes forward or backward at random, 50/50, like a coin flip.

The tilts no longer pile up in one direction. Some steps cancel others, like a drunk person's walk: forward, back, forward, forward, back…

This is a classical random walk, not a quantum random walk. The coin flips are ordinary randomness chosen by a normal computer before each run. (A quantum random walk is a different thing: the walker goes both ways at once and the paths interfere like waves, which is closer to the untwirled, angles-add-up behaviour.)

Averaged over many random twirls, the arrow doesn't turn: it points up on average, but it gets shorter. Each gate shrinks it by the same factor, cos 12° ≈ 0.978. The shrinks multiply, so the ⟨Z⟩ expectation value is (cos 12°)k.

One important detail: this shrinking is an average over many randomized copies of the circuit. Each single copy still has its 12° twist, just pointing forward or backward. That's why using twirling means running many randomized copies and averaging their results.

A caveat on "direction": "Random direction" here means only that each twist randomly goes forward or backward. The end result is that the average arrow never turns, it only shrinks, and only along the X, Y and Z axes. Which axes shrink depends on the error: for our twist around X, the X part of the arrow is untouched and only the Y and Z parts shrink. Our arrow points along Z, which is why ⟨Z⟩ shrinks.

For a twist around a tilted axis, twirling turns it into one random choice at each gate: do nothing, or apply an X, Y or Z flip, each with its own probability. (It is one choice among four options, not three separate coin flips.) So the coin flips are the mechanism, and "noise lined up with X, Y, Z" is the result.

The maths behind the two formulas

Optional. This shows where cos(k·θ) and (cos θ)k come from, using only rotations of the Bloch arrow. θ is the error angle per gate (12° in our example).

Show the derivation

Step 1: what one twist does to the arrow

Write the Bloch arrow as three numbers (x, y, z). Our starting arrow, pointing straight up, is (0, 0, 1), and ⟨Z⟩ is simply its z number. A twist by angle φ around the X axis leaves x alone and turns the (y, z) part like the hand of a clock:

x → x
y → y·cos φ − z·sin φ
z → y·sin φ + z·cos φ

In quantum notation this twist is written RX(φ) = e−iφX/2.

Step 2: without twirling, the angles add → cos(k·θ)

Twisting by θ and then by θ again around the same axis is the same as one twist by 2θ. So k identical twists make one twist by k·θ:

RX(θ) · RX(θ) · … · RX(θ)  (k times)  = RX(k·θ)

Put φ = k·θ and the starting arrow (0, 0, 1) into Step 1:

(0, 0, 1) → (0, −sin(k·θ), cos(k·θ))
so ⟨Z⟩ = cos(k·θ)

The arrow keeps its full length (sin² + cos² = 1); only its direction changes. With θ = 12° this gives the untwirled column: cos 12° = 0.978, cos 36° = 0.809, cos 60° = 0.500, and so on.

Check with probabilities: after k twists the state is cos(kθ/2)|0⟩ − i·sin(kθ/2)|1⟩, so P(0) = cos²(kθ/2) and P(1) = sin²(kθ/2). Then ⟨Z⟩ = P(0) − P(1) = cos²(kθ/2) − sin²(kθ/2) = cos(k·θ), by the double-angle rule.

Step 3: what twirling does to one twist → +θ or −θ

Twirling sandwiches the twist between a random Pauli and its undo. For a twist around X:

I · RX(θ) · I = RX(+θ)
X · RX(θ) · X = RX(+θ)
Y · RX(θ) · Y = RX(−θ)
Z · RX(θ) · Z = RX(−θ)

Why: X commutes with itself, so sandwiching with X changes nothing. Y and Z anticommute with X (swapping their order flips the sign: Y·X = −X·Y), so sandwiching with them reverses the twist. Two of the four choices keep +θ and two give −θ, so each gate's twist is +θ or −θ with 50/50 odds.

The same rule holds for twists around Y or Z: the matching Pauli keeps the sign, and the other two flip it.

TwistIXYZ
around X+θ+θ−θ−θ
around Y+θ−θ+θ−θ
around Z+θ−θ−θ+θ

Step 4: averaging +θ and −θ → the arrow shrinks by cos θ

Apply Step 1 with φ = +θ and with φ = −θ (using sin(−θ) = −sin θ and cos(−θ) = cos θ):

twist +θ:  (x,  y·cos θ − z·sin θ,   y·sin θ + z·cos θ)
twist −θ:  (x,  y·cos θ + z·sin θ,  −y·sin θ + z·cos θ)
average:   (x,  y·cos θ,  z·cos θ)

The sin θ parts point opposite ways and cancel. What's left: x is untouched, and y and z are each multiplied by cos θ. The arrow doesn't turn; it shrinks. (Averaging the arrows is allowed because the final answer is an average over many randomized runs, and ⟨Z⟩ averages the same way.)

Step 5: k twirled gates → (cos θ)k

Each gate is twirled with its own independent coin flip, so each gate multiplies z by another cos θ:

z:  1 → cos θ → (cos θ)2 → … → (cos θ)k
so ⟨Z⟩ = (cos θ)k

With θ = 12°, cos 12° = 0.978, which gives the twirled column: 0.978, 0.9783 = 0.936, 0.9785 = 0.895, and so on.

This is an exponential decay: (cos θ)k = ek·ln(cos θ), and ln(cos 12°) ≈ −0.022, so ⟨Z⟩ shrinks by about 2.2% with every gate.

Step 6: why folding can cancel (one simple model)

Let G be the hardware's version of an ideal gate U, with the twist attached: G = U · RX(θ). If the reverse gate is built as the exact reverse of G, it is G† = RX(−θ) · U† (the † means "reverse"). Folding then gives:

G · G† · G = U·RX(θ) · RX(−θ)·U† · U·RX(θ)
          = U · RX(θ) = G

The +θ and −θ cancel, and U†·U does nothing, so three gates carry the error of only one. Real hardware need not build the reverse gate this way, which is why the errors can also add up or only partly cancel.

What ZNE does with each column

ZNE measures at 1×, 3× and 5× noise (k = 1, 3, 5), fits a curve through those points, and extends it back to k = 0. The right answer there is 1.000. A common choice of curve is an exponential decay.

  • Twirled (0.978, 0.936, 0.895): these follow a clean exponential, so the curve extends back to 1.000 exactly ✓
  • Untwirled (0.978, 0.809, 0.500): forcing an exponential curve through these points gives about 1.21 at k = 0 ✗. That value is impossible, since "up" can't exceed 1. It is 21% off, while the plain 1× measurement was only about 2% off. Here ZNE made the answer worse.

A caveat: the choice of curve matters. ZNE isn't tied to exponentials. It can also fit a straight line or a quadratic (a parabola-shaped curve). Here is what each choice gives:

Curve fittedUntwirled → k = 0Twirled → k = 0
Straight line1.1210.999
Quadratic1.0101.000
Exponential1.2141.000

The quadratic rescues the untwirled data. That's because, over the first few gates, a small twist bends like a parabola, so a parabola fits it. The twirled data comes out right with every curve.

So the real lesson is: ZNE works when the fitted curve matches the true shape of the noise. On real hardware, twists and random kicks are mixed together, so without twirling you can't know which curve to trust. Twirling makes the shape predictable, so the choice of curve stops being a gamble.

One more trap: the noise-boosting can undo itself

ZNE often boosts noise by folding: gate → reverse gate → gate. The ideal result is the same as one gate, but you'd expect 3× the noise.

If the gate over-rotates by +12° and the reverse gate over-rotates by 12° in the opposite direction, those two cancel exactly. You think you ran at 3× noise, but the arrow only tilted 12°, which is 1× noise, so your data points sit at the wrong noise levels. Whether this happens depends on how the hardware builds the reverse gate: on real chips, the errors can cancel, add up, or land somewhere in between.

With twirling, the twists become random forward/backward steps that no longer line up neatly, either to cancel or to add up, so the boosted noise grows much more regularly. It's still not a guaranteed, exact 3×, but it's far closer to what ZNE assumes.

Where twirling really is required: IBM's ZNE can also boost noise a different way, called PEA (probabilistic error amplification). PEA first measures the hardware's noise as a list of random-flip probabilities, then adds extra noise by inserting more random flips. That list only describes the hardware after twirling, so for PEA, twirling isn't just helpful, it's required.

Summary

A coherent error is a twist whose angles add up, so the result follows a cosine wave, cos(k·θ): it swings and can even come back. Pauli twirling randomly flips each twist forward or backward (a classical random walk). Averaged over many randomized copies, this turns the twist into a steady shrink that follows (cos θ)k. A steady, predictable shrink is much easier for ZNE to extend back to zero noise.

Twirling doesn't lower the average amount of noise. It changes its shape: errors stop piling up in one direction, which makes ZNE's job far more reliable.
